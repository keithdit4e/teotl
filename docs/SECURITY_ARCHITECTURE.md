# Teotl Security & Compliance Architecture

Security-first design for autonomous agents with security practices informed by GDPR, SOC2, and HIPAA frameworks.

> **Scope:** This document covers the `SecurityPolicy` system in `teotl/core/security/`
> (the `security.yaml` generated by `teotl onboard`, with presets `strict`, `moderate`,
> `permissive`, `autonomous-dev`). It is separate from the agent guardrail policy passed as
> `Agent(policy="minimal" | "standard" | "strict")` — see [GUARDRAILS.md](GUARDRAILS.md).

> **Note:** Teotl has not undergone formal compliance audits. The security features described here are designed with these frameworks in mind, but users requiring certified compliance should conduct their own assessments.

## Design Principles

1. **Security by Default** - Wizard generates safe security.yaml
2. **Configurable** - Users choose security level and logging
3. **Transparent** - All security events logged and auditable
4. **Non-Intrusive** - Enforcement is a separate layer from the agent's prompt
5. **Compliance-Informed** - Security practices aligned with GDPR, SOC2, HIPAA frameworks

## Components

### 1. Policy System (`teotl/core/security/policy.py`)

**Purpose:** Define and load security policies

**Policy Structure:**
```yaml
# security.yaml
version: "1.0"
agent_id: "my-agent"

# Log level: minimal, standard, detailed, paranoid
log_level: "standard"

network:
  mode: "allowlist"  # allowlist, denylist, permissive
  allowed_domains:
    - "*.anthropic.com"
    - "*.openai.com"
    - "api.github.com"
  blocked_domains:
    - "*.facebook.com"
  require_approval:  # Interactive mode only
    - "*.amazonaws.com"

filesystem:
  mode: "restricted"  # restricted (alias for allowlist), allowlist, denylist, permissive
  allowed_paths:
    - "~/.teotl/agents/my-agent/**"
    - "/tmp/**"
  readonly_paths:
    - "~/Documents/**"
  blocked_paths:
    - "~/.ssh/**"
    - "~/.aws/**"
    - "/etc/**"
  max_file_size_mb: 10

tools:
  allowed:
    - "read_file"
    - "write_file"
    - "web_search"
    - "list_directory"
  blocked:
    - "execute_shell"  # Too dangerous
  require_approval:
    - "send_email"
    - "create_pull_request"

cost_limits:
  max_per_hour: 5.00
  max_per_day: 50.00
  max_per_month: 500.00
  currency: "USD"

rate_limits:
  max_api_calls_per_minute: 20
  max_tokens_per_hour: 100000

data_privacy:
  redact_pii: true  # Redact PII from logs
  encrypt_logs: false
  retention_days: 90  # Auto-delete old logs

compliance:
  gdpr_enabled: true
  soc2_enabled: true
  hipaa_enabled: false

sandbox:             # OS-level sandbox settings
  enabled: true
  allowed_paths:
    - "~/.teotl/agents/my-agent/**"
    - "/tmp/**"
  allowed_domains:
    - "*.anthropic.com"
  max_memory_mb: 1024
  max_cpu_seconds: 300
```

**Policy Class:** `SecurityPolicy` is a dataclass with one field per section
(`network`, `filesystem`, `tools`, `cost_limits`, `rate_limits`, `data_privacy`,
`compliance`, `sandbox`) plus `version`, `agent_id`, and `log_level`.

```python
from pathlib import Path

from teotl.core.security import SecurityPolicy

# From a preset: "strict", "moderate" (default), "permissive", "autonomous-dev"
policy = SecurityPolicy.create_default("my-agent", "moderate")

# From a file or dict
policy = SecurityPolicy.from_file(Path("security.yaml"))
policy = SecurityPolicy.from_dict({"agent_id": "my-agent", "log_level": "standard"})

# Query it
policy.network.allows("api.github.com")                       # -> bool
policy.filesystem.allows("/tmp/out.txt", write=True)          # -> bool
policy.tools.allows("execute_shell")                          # -> bool

# Save it
policy.to_yaml(Path("security.yaml"))
```

### 2. Audit Logger (`teotl/core/security/audit.py`)

**Purpose:** Log all security-relevant events

**Log Levels:**

- **minimal** - Only security violations
- **standard** - Violations + tool calls + costs
- **detailed** - Standard + LLM prompts/responses (PII redacted)
- **paranoid** - Everything including full prompts

**JSONL Format:** one `AuditEntry` per line, written to `<workspace>/audit/YYYY-MM.jsonl`
(rotated monthly; `None` fields are omitted). Illustrative entries:
```jsonl
{"timestamp":"2026-03-26T14:30:00","agent_id":"my-agent","event_type":"tool_call","tool":"web_search","args":{"query":"AI news"},"allowed":true,"cost":0.001,"duration_ms":1500,"hipaa_phi_accessed":false,"pii_redacted":false}
{"timestamp":"2026-03-26T14:31:00","agent_id":"my-agent","event_type":"policy_violation","tool":"facebook.com","allowed":false,"policy_violated":"network","violation_reason":"Domain 'facebook.com' is blocked by network policy","hipaa_phi_accessed":false,"pii_redacted":false}
```

**Compliance Fields:**

**GDPR:**
- Data subject ID (user)
- Purpose of processing
- Legal basis
- Data retention period
- PII redaction flag

**SOC2:**
- Access controls applied
- Authentication method
- Authorization checks
- Audit trail integrity

**HIPAA:**
- PHI access logged
- Encryption status
- Access justification
- Audit log integrity

**Audit Entry** (`teotl.core.security.AuditEntry`):
```python
@dataclass
class AuditEntry:
    timestamp: str  # ISO 8601 format
    agent_id: str
    event_type: str  # tool_call, tool_result, policy_violation, cost_limit, etc.

    # Event details
    tool: str | None = None
    args: dict | None = None
    result_summary: str | None = None

    # Security
    allowed: bool = True
    policy_violated: str | None = None
    violation_reason: str | None = None

    # Performance
    duration_ms: int | None = None
    cost: float | None = None
    tokens_used: int | None = None

    # Compliance (GDPR / SOC2 / HIPAA)
    gdpr_data_subject: str | None = None
    gdpr_purpose: str | None = None
    gdpr_legal_basis: str | None = None
    soc2_auth_method: str | None = None
    soc2_access_granted: bool | None = None
    hipaa_phi_accessed: bool = False
    hipaa_access_justification: str | None = None

    # Privacy
    pii_redacted: bool = False
```

`AuditLogger(policy, workspace_dir)` provides async `log_tool_call`, `log_tool_result`,
`log_violation`, `log_cost_limit`, `log_rate_limit`, `log_llm_prompt`, `log_hipaa_access`,
plus `read_logs(...)` and `cleanup_old_logs()`.

### 3. Enforcement Engine (`teotl/core/security/enforcement.py`)

**Purpose:** Enforce policies at runtime

**Enforcement Points:**

1. **Before Tool Execution** - Check if tool call is allowed
2. **Network Requests** - Validate domains
3. **File Operations** - Check paths
4. **Cost Tracking** - Enforce limits
5. **Rate Limiting** - Prevent abuse

**Enforcer Class** (simplified):
```python
class SecurityEnforcer:
    """Enforces security policies at runtime."""

    def __init__(
        self,
        policy: SecurityPolicy,
        workspace_dir: Path,
        sandbox: SandboxManager | None = None,
    ):
        self.policy = policy
        self.workspace_dir = workspace_dir
        self.sandbox = sandbox
        self.audit = AuditLogger(policy, workspace_dir)
        self.cost_tracker = CostTracker(policy.cost_limits, workspace_dir / "security" / "costs.json")
        self.rate_limiter = RateLimiter(policy.rate_limits)

    async def enforce_tool_call(
        self,
        tool_name: str,
        args: dict,
    ) -> tuple[bool, str | None]:
        """
        Check if tool call is allowed.

        Returns:
            (allowed, reason_if_blocked)
        """
        # 1. Check tool policy
        if not self.policy.tools.allows(tool_name):
            reason = f"Tool '{tool_name}' blocked by policy"
            await self.audit.log_violation("tool", tool_name, reason)
            return False, reason

        # 2. Check network policy (if applicable)
        if tool_name in ["web_search", "fetch_url"]:
            domain = self._extract_domain(args)
            if not self.policy.network.allows(domain):
                reason = f"Domain '{domain}' blocked by network policy"
                await self.audit.log_violation("network", domain, reason)
                return False, reason

        # 3. Check filesystem policy (if applicable)
        if tool_name in ["read_file", "write_file"]:
            path = args.get("path") or args.get("file_path")
            if not self.policy.filesystem.allows(path, write=(tool_name == "write_file")):
                reason = f"Path '{path}' blocked by filesystem policy"
                await self.audit.log_violation("filesystem", path, reason)
                return False, reason

        # 4. Check cost limits
        estimated_cost = self._estimate_cost(tool_name, args)
        if not self.cost_tracker.would_allow(estimated_cost):
            reason = f"Cost limit exceeded (estimated: ${estimated_cost})"
            await self.audit.log_violation("cost_limit", tool_name, reason)
            return False, reason

        # 5. Check rate limits
        if not self.rate_limiter.would_allow():
            reason = "Rate limit exceeded"
            await self.audit.log_violation("rate_limit", tool_name, reason)
            return False, reason

        # Allowed!
        await self.audit.log_tool_call(tool_name, args, allowed=True)
        return True, None
```

### 4. Cost Tracker (`teotl/core/security/cost_tracker.py`)

**Purpose:** Track and limit costs

`CostTracker(limits: CostLimits, storage_path: Path)` persists cost records to JSON and
provides `would_allow(estimated_cost)`, `record_cost(...)`, `get_remaining()`, and
`get_current()`. The same module defines the per-minute `RateLimiter(limits: RateLimits)`
used by the enforcer (distinct from `teotl.primitives.guardrails.rate_limiter.RateLimiter`).

## Using the Enforcer

`SecurityEnforcer` is a standalone component: it is not automatically invoked by
`Agent.run()`. To enforce a `SecurityPolicy` around your own tool execution, call it
before running each tool:

```python
from pathlib import Path

from teotl.core.security import SecurityEnforcer, SecurityError, SecurityPolicy

policy = SecurityPolicy.from_file(Path("~/.teotl/my-agent/security.yaml").expanduser())
enforcer = SecurityEnforcer(policy, workspace_dir=Path("~/.teotl/my-agent").expanduser())


async def execute_tool(tool_name: str, args: dict, run_tool):
    allowed, reason = await enforcer.enforce_tool_call(tool_name, args)
    if not allowed:
        raise SecurityError(reason)
    return await run_tool(args)
```

## Wizard Integration

`teotl onboard` (alias `teotl wizard`) includes a security step that asks for:

1. **Security preset** — `moderate` (recommended), `strict`, or `permissive`
   (`autonomous-dev` is auto-selected for goals-based autonomous agents)
2. **Compliance features** — optional GDPR / SOC2 / HIPAA flags
3. **Audit log level** — `standard` (recommended), `minimal`, `detailed`, `paranoid`

It then writes `security.yaml` into the agent's workspace using
`SecurityPolicy.create_default(agent_id, preset)` plus your compliance settings.
The moderate preset, for example, allows `*.anthropic.com`, `*.openai.com`,
`api.github.com`, `*.google.com`, and `*.wikipedia.org`, restricts file access to the agent
workspace and `/tmp` (with `~/Documents` read-only), blocks `~/.ssh`, `~/.aws`, and `/etc`,
and sets cost limits of $5/hour and $50/day.

## Management Tools

The `teotl security` command reads the audit logs and policy in an agent workspace
(default `~/.teotl/my-agent`; override with `--workspace/-w`):

```bash
# View recent audit logs
teotl security logs --workspace ~/.teotl/my-agent --days 1

# Show only violations
teotl security logs --violations-only

# Filter by event type
teotl security logs --type tool_call,policy_violation

# Generate a compliance report (last 30 days by default) and save as JSON
teotl security report --days 90 --output compliance_report.json

# Show current security status (policy, compliance flags)
teotl security status
```

Planned (not yet available): framework-specific compliance reports (GDPR/SOC2) and a
policy validator/tester command.

## Security Recommendations

**For Users:**

1. **Start with Moderate** - Good balance for most use cases
2. **Enable compliance** - If handling regulated data
3. **Review audit logs** - Regularly check for violations
4. **Adjust as needed** - Loosen/tighten based on experience

**For Developers:**

1. **Never bypass security** - Always go through enforcer
2. **Log everything** - When in doubt, log it
3. **Fail secure** - Default to denying, not allowing
4. **Test violations** - Ensure policies actually work
